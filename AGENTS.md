## Design system

Tokens live in `app/globals.css` under `@theme`. Committed dark, single world —
there is no light mode and none is wanted.

**"Ashfield"** — the client's own palette. Three roles, and the whole design
depends on not blurring them:

- **ash is the world** — ground `--color-void #0A0A0B`, surfaces `--color-ash`,
  `--color-ash-2`, type `--color-bone`/`-2`/`-3`. Glass surfaces via `glass`.
- **lime is interaction** — `--color-lime #BFF23C`. *Anything you can touch,
  focus, or act on. Nothing decorative.*
- **brown is atmosphere** — `--color-bark`, `--color-clay`, `--color-tan`. Light
  fields, callouts, meta, warmth. *Nothing you can click is brown.*

Project badges are information rather than controls, which is why they sit in the
brown/ash half. Keep that split — it is what lets the page teach you where to
click without instructions.

**Type** — Bricolage Grotesque (`--font-display`) and JetBrains Mono
(`--font-mono`). Utilities: `eyebrow` (small caps labels), `grain` (film grain,
replaced the old ruled grid). The hero name has its own face via
`--font-signature` — swap it in `app/layout.tsx` alone if the letterforms are
wrong; nothing else depends on it.

## Motion

Primitives are isolated in `components/motion/` (plus `components/ui/Button.tsx`)
so they can be tuned in one place:

| File | Does |
| --- | --- |
| `InteractiveField.tsx` | The ground. Brown atmosphere + grain at rest; a canvas dot-lattice exists **only within a radius of the cursor**, pushed away from it and tinted tan→lime toward the centre. Background is brown until you touch it, lime where you do. |
| `Cursor.tsx` | A blinking **terminal block caret**, not a dot-and-ring — that was rejected as too common. Over anything clickable it squares into a lime diamond and a `› label` prompt capsule trails in, decoded with the same scramble. |
| `KineticName.tsx` | Hero name as individually reactive letters. Set in **Unbounded** (`--font-signature`, axis `wght` 200–900), carrying a resting gradient bone→tan→lime across the whole name; cursor proximity drives weight, tracking, lift and a push toward lime. No outline treatment — the client rejected it twice. |
| `StatusDot.tsx` | "Open to work" ping. Rings start *and* end at opacity 0 so the loop seam is invisible; two rings offset by half a cycle. |
| `Scramble.tsx` | Headings decode out of glyph noise on scroll-in |
| `Reveal.tsx` | Scroll-triggered entrance, fires once |
| `TiltCard.tsx` | 3D tilt + pointer-tracking light |
| `ScrollProgress.tsx` | Gradient progress bar |
| `Marquee.tsx` | Seamless ticker (list rendered twice, translated -50%) |
| `ui/Button.tsx` | The site's only button. Ink fill grows from the point the cursor crossed the edge; the label decodes **in place**. Do not reintroduce the rolling second copy — two things moving at once made the decode read as a stutter. |

Rules that must hold:

1. **Every motion component checks `useReducedMotion`** and degrades to static.
2. **Pointer-driven effects bind only to a fine pointer / `pointerType === "mouse"`.**
   On a phone there is no hover and the transform would only ever fire mid-tap.
3. **`Cursor` hides the native cursor only once it has actually mounted** — it
   sets `html.cursor-custom` itself. Never move that to a static class, or touch
   and reduced-motion visitors lose their cursor entirely. Inputs and
   `contenteditable` keep the system caret.
4. **The name face must stay a *variable* font.** `app/layout.tsx` loads it with
   **no `weight` key**. Adding `weight` collapses it to static instances and
   `KineticName` silently stops animating.
5. **Time-based progress, never frame counting.** `Scramble` uses elapsed
   wall-clock time. Background tabs clamp timers to ~1Hz; counting ticks strands
   text as gibberish. That bug was fixed once already — do not reintroduce it.
6. **rAF loops must sleep when settled.** `InteractiveField` runs only while
   something is still moving. A stationary pointer must burn nothing.
7. **New interactive elements need `data-cursor` / `data-cursor-label`** to read
   correctly under the custom cursor. Lime-filled controls take
   `data-cursor="dark"` so the cursor inverts and stays visible on its own
   interaction colour.
8. **Scroll reveals prerender at `opacity:0`.** The `<noscript>` block in
   `app/layout.tsx` forces them visible when JS is off. If you add a new reveal
   mechanism, keep that fallback working.

## Content rules — non-negotiable

All copy lives in `content/site.ts`. Never write facts into components. The rules
are documented at the top of that file; in short:

1. **No CGPA anywhere.** Education carries no grades at all, so the omission is
   consistent rather than conspicuous. (The figure itself is deliberately not
   recorded in this repo — see the .gitignore for why.)
2. **UCBL work is capability-level only.** No database versions, host names,
   instance counts or topology — that maps a regulated bank's estate and would
   likely breach his internship terms. The project page renders an explicit
   "On disclosure" note. **The wording still needs his supervisor's sign-off
   before launch.**
3. **No referees named.** "Available on request" only.
4. **Claim only what the source documents claim.** A previous draft invented
   "librosa" and "TensorFlow" for the thesis stack. Neither appears in his CV or
   summary. Do not add a library because a project probably used one.
5. **Coursework is labelled as coursework.** Each project carries a `badge`, and
   the work section says so out loud. Research on fresher portfolios is clear that
   owning this beats letting a recruiter notice it.
6. **Every project needs a `learned` line.** This is the single highest-value
   element for a fresher — hiring managers want lessons, bugs and iteration, not
   more polish. Keep them specific and keep the admissions of getting it wrong.

## Verification caveat

The in-app browser pane in previous sessions reported `visibilityState: "hidden"`,
so `requestAnimationFrame` never ran and **no animation has ever been visually
confirmed by an agent**. Canvas output and reveal states were verified by sampling
pixels and reading inline styles instead. If you need to confirm something visual,
open it in the user's real browser (`Start-Process "http://localhost:3002/"`) and
ask them — do not claim a visual check you did not perform.

## Known gaps

- **Repo links are deliberately not wired up.** None of his 16 GitHub repos has a
  README or description; `DBInventory` is public but empty. Research is emphatic
  that recruiters want working links, so READMEs are the highest-value remaining
  task — bigger than any design change.
- No CV PDF yet, so there is no download in the nav.
- Portrait is a formal white-background ID shot from the CV; unused so far.
- Thesis figures and the IEEE paper reference are still missing.
- **Mobile has never been verified on a real device.** (Emulated at 390×844 it
  renders with no horizontal overflow, and neither the custom cursor nor the
  canvas mounts on a coarse pointer.)
- **Hydration warning under `prefers-reduced-motion: reduce`.** `useReducedMotion`
  returns `null` on the server and `true` on the client, so any component that
  *branches its tree* on it mismatches — `app/template.tsx` (wrapper vs
  fragment) and the entrance props in `Hero`/`Reveal`/`ProjectGrid`. React
  recovers by re-rendering, and content stays visible, but the fix is to keep the
  markup identical and vary only transition timing (as `InteractiveField` now
  does). Only reproducible with reduced motion on.
- No favicon: `/favicon.ico` 404s and is the one console error on every page.
- Home route JS is heavy — framework floor plus `motion` (~34KB gz). An earlier
  plan promised <100KB gz and that was never achievable with Next App Router.
